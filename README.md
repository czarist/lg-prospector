# LG Prospector

**v2.0.1** — A Brazilian B2B lead factory. It finds companies, attaches a real mailbox, syncs them to EspoCRM, and sends a niche-specific HTML pitch — slowly enough that it does not look like a blast.

Hunts only **discover**. **Mailman** is the only sender. **Cockpit** starts both and shows the live panel.

## What it does

LG Prospector is built for **Brazilian B2B**, not generic web scraping.

A typical run looks like this:

1. **Discover** companies in a niche and city — law firms, agencies, IT shops, media groups, politicians, or any plausible local business.
2. **Enrich** until there is a real mailbox on a plausible domain (MX check, geo/nationality filters, public-body block).
3. **Sync** Account + Contact + Lead into [EspoCRM](https://trentincrm.com.br).
4. **Send** a pre-written HTML template. The model never writes or rewrites the email.

Two hunt processes fill the CRM. A third process, **mailman**, is the only one that talks to SMTP. That split is intentional: prospecting can run hard while sending stays slow — **one niche + one generalist every 2–5 minutes** — so Zoho does not treat it as a blast.

```
hunt (niche)       ── discover → enrich → CRM ──┐
                                                ├─► contacts idle ≥ 4 days ─► mailman ─► SMTP
hunt (generalist)  ── discover → enrich → CRM ──┘
```

| Process | Job | Does it send mail? |
|---------|-----|--------------------|
| Niche hunt | City × niche ladder (Porto Alegre first, then capitals, then RS hubs) | No |
| Generalist hunt | Any plausible local business; 4-day wait before it is eligible | No |
| Mailman | Picks one idle niche contact + one idle generalist; random 2–5 min pause | **Yes** |
| Cockpit | Starts the three processes and shows progress, ETAs, and host health | No |

`q` in the cockpit closes the panel. The three workers keep running until `./cockpit --stop`.

## How AI is used

The LLM is **optional and local**. On this host it is **Qwen 2.5** behind **LiteLLM** (`MODEL=local-main`, `http://localhost:4000/v1`), OpenAI-compatible. **LangGraph / LangChain** orchestrate the campaign graph; they do not compose marketing copy.

| Job | Model role |
|-----|------------|
| Discover | Score a SERP candidate: keep / drop, clean name (`HUNT_USE_LLM`) |
| Enrich | Judge whether a free-mail or odd address belongs to the business |
| Review scripts | Re-score leads already in the database |
| Email body | **None.** Templates live on disk. The AI picks the file; it never edits HTML |

Concurrency stays at **1** so the local GPU can breathe. If LiteLLM is down, hunts still run — they just skip the model filter.

## One command: cockpit

Starts the niche hunt, the generalist hunt, and mailman, then opens the terminal panel (progress, ETAs, CPU / RAM / GPU, disks, MySQL, Redis, LiteLLM, CRM, site).

```bash
./cockpit            # start whatever is missing + panel
./cockpit --attach   # panel only
./cockpit --stop     # stop all three
```

`q` closes the panel. Processes keep running.

## Hunts (prospect only)

Each job is **discover → enrich → CRM**. Nothing is emailed here.

Niche hunt walks a city ladder (Porto Alegre first, then capitals, then RS hubs, then other large cities) and a set of niches. Generalist hunt finds any plausible local business and waits **4 days** before mailman may write to it.

```bash
# inspect the city × niche queue
python scripts/hunt_loop.py --plan-only --focus-rs --max-tier 2

# one pass, Rio Grande do Sul only
python scripts/hunt_loop.py --only-rs --once -n 5

# continuous (resumes from hunt_loop_state.json)
python scripts/hunt_loop.py --focus-rs --max-tier 2 -n 5 --pause 8

python scripts/hunt_generalista.py --focus-rs --max-tier 3 -n 8
```

### Hunt load knobs

| Env | Default | Effect |
|-----|---------|--------|
| `SEARCH_CONCURRENCY` | `1` | One search at a time |
| `SEARCH_MIN_INTERVAL_SECONDS` | `0.9` | Pause between SERPs |
| `ENRICH_CONCURRENCY` | `1` | One lead at a time |
| `ENRICH_PLAYWRIGHT` | `false` | Browser only if `true` |
| `HUNT_USE_LLM` | `true` | Qwen filters discover candidates |
| `LLM_CONCURRENCY` | `1` | Never parallel on the local model |
| `MODEL` | `local-main` | LiteLLM id for local Qwen |
| `DISCOVER_MIN_LLM_SCORE` | `40` | `keep=true` is ignored below this |

## Mailman (send only)

Looks at contacts that have **not received mail in the last 4 days**. Each batch is **one niche + one generalist**. If either side is empty, it waits. Pause between batches is random **2–5 minutes**.

```bash
python scripts/mailman.py            # loop
python scripts/mailman.py --once     # one batch
python scripts/mailman.py --plan     # queue only
python scripts/mailman.py --dry-run --once
```

The same address is not emailed again before `EMAIL_COOLDOWN_DAYS` (default 4).

## Pipeline

```
created → discover → enrich → crm          # hunts
                              ↘ mailman → sent
```

| Stage | What it does |
|-------|----------------|
| `discover` | Find companies (Serper / DDG / OSM) |
| `enrich` | Domain email (scrape + `site:` / `@domain`) |
| `crm` | Account + Contact + Lead in EspoCRM |
| `dispatch` | HTML template via SMTP (CID images) — mailman, not the hunt |

No domain email after the multi-pass → item **discarded**.
